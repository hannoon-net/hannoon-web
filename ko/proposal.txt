1. 개요 및 종합 진단 요약
--------------------------------------------------------------------------------
현재 한눈 이지빌 웹사이트는 Tailwind CSS 기반의 세련된 UI, 직관적인 비주얼, 
그리고 본문 텍스트 내에 핵심 타겟 키워드(정기 청구, 전자세금계산서, 복식부기, 
화물·택배·중장비 지입, N:N 교차 청구 등)가 풍부하게 반영되어 있습니다.

그러나 keyword.txt에 도출된 방대한 검색 수요와 잠재 고객을 실제로 유입시키기에는 
'테크니컬 SEO(검색엔진 기술 규격)', '메타 태그 커버리지', '페이지별 키워드 타겟팅 구조' 
측면에서 상당한 보완이 필요한 상태입니다.

[핵심 진단 결과 요약]
* 검색 크롤링 인프라 전무: robots.txt, sitemap.xml, canonical 태그 누락
* 메타 태그 불균형 심각: features.html, manual.html, service-fee.html 등 주요 
  페이지에 meta description/keywords/og 태그 완전 부재
* 검색 볼륨 흡수력 한계: Title 및 H1 태그가 문장형 감성 카피 위주로 되어 있어, 
  핵심 검색 키워드(무료 세금계산서 발행 프로그램, 부동산 임대관리 등)에 대한 
  검색 노출 점수(Relevance Score)가 낮음
* 산업별 롱테일 키워드 분산: 6대 핵심 산업(부동산, 화물지입, 렌탈 등)이 단일 
  페이지(use-cases.html)의 JS 탭(display:none)으로 묶여 있어 개별 산업 키워드 
  검색 시 검색 순위 상위 노출에 불리함

2. 세부 문제점 분석 (keyword.txt 대조)
--------------------------------------------------------------------------------

(1) 메타 태그(Meta Tags) 및 Title 태그의 결손
- index.html, use-cases.html, download.html에만 meta description/keywords가 존재함.
- 핵심 랜딩페이지인 features.html(주요 기능)을 비롯해 manual.html, server-manual.html, 
  server-specs.html, service-fee.html, csv_guide.html 등 7개 이상의 페이지에 
  meta description, meta keywords, Open Graph(SNS 미리보기) 태그가 전무함.
- features.html의 Title이 단순히 <title>주요 기능 소개 - 한눈 이지빌</title>로 
  설정되어 있어 '무료 정기 청구', '전자세금계산서 연동', '복식부기 장부' 키워드 검색 시 
  검색엔진 결과 목록에서 경쟁력이 떨어짐.

(2) H1 시맨틱 태그의 키워드 부재
- index.html의 H1: "복잡한 정기 청구와 세금계산서 발행, 클릭 한 번으로 한눈에 해결하세요"
  -> 브랜드명과 핵심 명사형 키워드가 H1에 직접 포함되지 않음.
- features.html의 H1: "주요 기능 한눈에 보기"
  -> 정기 청구, 세금계산서, 회계 자동화 등 검색엔진이 색인할 주요 명사 키워드 누락.
- use-cases.html의 H1: "정기 청구가 필요한 모든 비즈니스, 한눈 이지빌로 클릭 한 번에 자동화"
  -> 화물 지입, 부동산 임대관리 등 핵심 타겟 산업명이 H1에 없음.

(3) 테크니컬 SEO(Technical SEO) 필수 자산 누락
- robots.txt 부재: 네이버 서치어드바이저 및 구글 봇에게 올바른 수집 권한 및 
  사이트맵 위치를 알려주지 못함.
- sitemap.xml 부재: 검색엔진이 서브페이지(서버 매뉴얼, 가이드, 단가표 등)를 
  신속하고 누락 없이 크롤링 및 인덱싱하지 못함.
- Canonical URL(<link rel="canonical" ...>) 누락: URL 파라미터나 접속 프로토콜 
  차이로 인한 중복 페이지(Duplicate Content) 패널티 방지 장치가 없음.
- 구조화 데이터(JSON-LD / Schema.org) 부재: 구글 검색 시 '소프트웨어 평점', 
  '무료 가격(0원)', 'FAQ 아코디언' 등이 리치 결과(Rich Results)로 노출되지 않음.

(4) 6대 산업별 롱테일 키워드의 단일 페이지 집중 한계
- use-cases.html 한 페이지 안에 부동산, 렌탈, 화물지입, IT SaaS, 용역, 정기구독 6대 
  산업군이 모두 들어가 있고 탭 클릭 시 display: none으로 전환됨.
- 검색 사용자가 "화물차 지입 관리 프로그램" 또는 "부동산 임대관리 프로그램"을 검색했을 때, 
  검색엔진은 해당 산업에만 특화된 단독 랜딩 페이지를 우선 순위로 노출함. 
  현재 구조로는 특정 산업 롱테일 키워드 1페이지 상위 노출에 불리함.

[제안 2] Open Graph (OG) 및 Twitter Card 태그 전 페이지 표준화
- 카카오톡, 네이버 블로그, 페이스북, 슬랙 등에 URL 공유 시 매력적인 썸네일과 미리보기가 
  노출되도록 모든 HTML 파일의 <head>에 아래 표준 태그를 적용:
  <meta property="og:type" content="website">
  <meta property="og:title" content="...">
  <meta property="og:description" content="...">
  <meta property="og:image" content="https://도메인/assets/og-image.png">
  <meta property="og:url" content="https://도메인/ko/hannoon-easybill/...">
  <meta name="twitter:card" content="summary_large_image">


[제안 3] 테크니컬 SEO 필수 파일 생성 및 정규 태그 적용

  1) robots.txt 생성 (루트 디렉토리):
     User-agent: *
     Allow: /
     Sitemap: https://도메인/sitemap.xml

  2) sitemap.xml 생성 (루트 디렉토리):
     모든 공개 페이지(index.html, features.html, use-cases.html, download.html, 
     manual.html, server-manual.html, service-fee.html 등)의 절대 URL, 수정일자, 
     우선순위(priority: 1.0, 0.8 등)를 명시하여 네이버 서치어드바이저 및 구글 서치콘솔에 등록.

  3) Canonical URL 삽입:
     모든 페이지의 <head>에 <link rel="canonical" href="해당페이지절대URL"> 추가.


[제안 4] Google 및 Naver 리치 검색 결과용 구조화 데이터(JSON-LD) 도입
- 구글 검색창에서 '소프트웨어', '무료', '기능' 등의 풍부한 스니펫이 노출되도록 index.html 
  및 download.html에 Schema.org JSON-LD 마크업 삽입:
  ```html
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "SoftwareApplication",
    "name": "한눈 이지빌 (Hannoon Easybill)",
    "operatingSystem": "Windows 10, Windows 11, Windows Server",
    "applicationCategory": "BusinessApplication",
    "offers": {
      "@type": "Offer",
      "price": "0",
      "priceCurrency": "KRW"
    },
    "description": "정기 청구, 전자세금계산서 국세청 전송, 4대 복식부기 회계 장부 자동 생성 무료 소프트웨어"
  }
  </script>
  ```


[제안 5] 본문 시맨틱 H1/H2 태그 및 앵커 텍스트(Anchor Text) 키워드 보강
- index.html의 H1 내에 '무료 정기 청구·세금계산서 프로그램' 핵심 키워드를 직접 포함:
  예: "정기 청구부터 전자세금계산서·복식부기까지, 무료 프로그램 한눈 이지빌로 원클릭 해결"
- features.html의 H1 변경:
  "한눈 이지빌 주요 기능 - 정기 청구·전자세금계산서·회계 장부 자동화"
- 텍스트 링크 개선:
  단순 "자세히 보기 &rarr;" 대신 "원클릭 청구 프로세스 자세히 보기", 
  단순 "다운로드" 대신 "한눈 이지빌 무료 다운로드" 형태로 키워드 포함형 앵커 적용.


[제안 6] 산업별(부동산, 화물지입 등) 전용 롱테일 랜딩 페이지 분리/확장 전략
- 현재 use-cases.html에 묶여 있는 6개 핵심 분야 중, 검색 수요와 전환 가치가 가장 높은 
  분야를 독립된 서브 URL로 분리 구축 권장:
  1) /cases/logistics.html (화물·택배·건설중장비 지입 관리 프로그램)
     -> 키워드: 화물지입프로그램, 지입료청구, 택배대리점정산, 중장비지입료
  2) /cases/real-estate.html (부동산 임대관리 및 월세·관리비 청구 프로그램)
     -> 키워드: 부동산임대관리프로그램, 월세청구, 상가관리비프로그램
  3) /cases/rental.html (차량·사무기기·가전 렌탈/리스 관리 프로그램)
     -> 키워드: 렌탈관리프로그램, 복합기렌탈청구, 렌터카월청구
- 분리된 페이지는 해당 업종 실무자가 검색하는 전문 용어와 고민을 집중적으로 다루어, 
  네이버/구글 검색 1페이지 상단 노출 확률을 300% 이상 증대시킵니다.


[제안 7] 정보성 검색 유입을 위한 '실무 가이드 / FAQ' 콘텐츠 확장 제안
- 프로그램 이름이나 솔루션을 바로 검색하지 않는 '정보 탐색형 사용자'를 대거 유입시키기 위한 
  가이드형 콘텐츠 신설 제안:
  - "엑셀로 관리하던 임대료 장부, 프로그램으로 자동 전환하는 법"
  - "화물 지입차주 월 관리비 및 보험료 세금계산서 발행 시 주의사항"
  - "복식부기 회계 원리 몰라도 분개장과 미수금 장부 만드는 팁"
  - "국세청 홈택스 직접 발행 vs 바로빌 API 연동 자동 발행의 차이점과 비용 비교"
- 이러한 정보성 콘텐츠는 상위 노출 후 한눈 이지빌 무료 다운로드로 자연스럽게 전환됩니다.

4. 우선순위별 실행 로드맵
--------------------------------------------------------------------------------

[1단계: 즉시 실행 (Quick Wins - 1~2일 내 완료 가능)]
1. features.html, download.html, service-fee.html 등 전 페이지 Title, Description, 
   Keywords 메타 태그 최적화 적용
2. Open Graph(og:) 및 Twitter 태그 전 페이지 일괄 삽입
3. 루트 디렉토리에 robots.txt 및 sitemap.xml 생성 및 등록
4. 각 페이지별 <link rel="canonical"> 태그 삽입

[2단계: 구조 최적화 (Short-term - 1주일 내 완료)]
1. index.html, features.html, use-cases.html의 H1, H2 헤딩 텍스트 키워드 보강
